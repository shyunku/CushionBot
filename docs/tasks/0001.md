## 기록

- 2026-11-18 11:12: 시안 8차 확정 후 시작.
- 2026-11-18 11:22: 구현 완료. 커밋 `928a85c`(API·정적 서빙), `e8f1267`(React 앱), `71bd3b9`(빌드 연결).
- 검증
  - JDK 18 + Gradle `compileJava` 성공, `pnpm build`(tsc + vite) 성공.
  - 정적 서빙: 자바 `StaticFileHandler`만 띄운 테스트에서 `/`, `/servers/..`, `/channel/..`가 index로 대체되고, `/assets/*.js`가 gzip + `immutable` 캐시로 나가며, `../` 경로 탈출은 index로 막히는 것을 확인했다.
  - 화면: 봇과 같은 JSON 형식의 합성 API(서버 3개, 30명, 60일)로 타임라인·hover 툴팁·휠 확대·채널 필터·랭킹·더보기(30일)·사람 페이지·공유 화면을 캡처해 시안과 비교했다.
  - 실제 봇(JDA)으로 API를 돌려 보지는 못했다(디스코드 토큰·Redis 필요). → 1.9
- 시안과 다른 점
  - 타임라인은 보이는 기간에 접속 기록이 있는 사람만 행으로 보여 준다(시안은 전원). 기록된 사람이 많은 서버에서 빈 행이 길게 늘어나는 것을 막기 위함.
  - 사람 페이지 요약 카드 이름에 "(최근 30일)"을 붙였다.
- 로딩 개선 방식: 계획의 "보는 기간만 내려주기" 대신 서버 하나의 전체 세션을 한 번에(gzip) 내려준다. 기록이 최대 1년만 보관되고, 랭킹·누적 통계가 전체 기간을 필요로 해서다. 느렸던 원인(사람마다 개별 요청 + 요청마다 디스코드 API 조회)은 묶음 API와 서버 쪽 멤버 캐시로 없앴다.
