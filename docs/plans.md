# Plans

## watcher 대시보드 봇 통합·리디자인 (#1)

최초 작성: 2026-11-18 10:02 / 갱신: 2026-11-18 11:07

### 배경

- `watcher/main.js`(Express + EJS)는 정적 파일과 값 3개(`botHost`, `botPort`, `channelId`)만 내려준다. 실제 데이터는 브라우저가 봇 HTTP 서버(7918)에서 직접 받는다.
- 이 때문에 포트가 둘(7918, 7919)이고, CORS 헤더가 필요하며, 페이지 요청마다 공인 IP를 외부 서비스에 조회한다.
- 현재는 봇이 시작할 때 `node main.js`를 하위 프로세스로 실행한다(`service/watcher/WatcherWebServer.java`). 통합이 끝나면 이 실행기는 없앤다.
- 처음 열 때 로딩이 매우 느리다. 코드에서 확인한 원인은 다음과 같다.
  - 프론트가 서버마다 `/guild/{id}`, 사람마다 `/user/{guild}/{user}`를 하나씩 순서대로 기다리며 요청한다(N+1 요청, 직렬).
  - `/user` 처리기는 요청마다 `retrieveMemberById(...).complete()`로 디스코드 REST API를 호출한다(사람 수만큼 외부 호출, 속도 제한 대상).
  - `/data`는 전체 기간의 기록을 한 번에 내려주고, SSE 이벤트가 올 때마다 전체를 다시 받는다.
  - SSE 연결마다 0.3초 간격으로 ping을 보낸다.

### 확정

- 대시보드는 CSR로 만들고 Vite + React로 다시 작성한다. 런타임에 Node 서버를 두지 않는다.
- 봇 HTTP 서버(7918)가 빌드 결과(`watcher/dist`)를 디스크에서 읽어 내려준다. 대시보드 주소는 `:7919`에서 `:7918`로 바뀐다.
- 페이지는 자신이 열린 주소(`location`)로 API를 호출하고, `channelId`는 URL 경로(`/channel/:id`)에서 읽는다.
- 빌드는 배포 때 서버에서 한다(`fastbuild.sh`에 `pnpm install`, `pnpm build` 추가). 빌드 결과물은 git에 넣지 않는다.
- UI/UX도 같이 개편한다. 시안: [pc-3.4.0-watcher-redesign-mock.html](designs/pc-3.4.0-watcher-redesign-mock.html)
- 시안 1·2차에서 고른 화면: 다크 슬레이트 테마, 아이콘 레일, 고정 이름 열 + 막대 뒤 아바타·이름, 기간 프리셋(최근 24시간/오늘/최근 7일), 오늘 요약 카드 4개, 지금 접속 중 채널별 칩, 채널 범례 + 필터, 카드형 툴팁, 스켈레톤 로딩, 공유 버튼 + 토스트.
- 사람별 대시보드 페이지를 추가한다(시안 3차). 타임라인에서 사람 이름을 누르면 바로 이동하고, 주소가 따로 있어 공유할 수 있다. 요약 카드(최근 30일 총 접속, 접속한 날, 평균 접속 길이, 가장 많이 간 채널), 시간대별 접속 빈도 그래프 + 요일×시간 히트맵, 일별 접속 시간(14일), 자주 간 채널 비율, 최근 접속 목록을 보여 준다. 시간대 그래프는 10분 단위로 계산한 부드러운 곡선이다(시안 4차).
- 들낙 지표: 5분 미만 접속(진행 중인 접속 제외)을 들낙으로 센다. 들낙 비율(전체 접속 중 들낙 비율)과 하루 평균 들낙 횟수(접속한 날 기준)를 둘 다 사람 페이지에만 표시한다(시안 4차). 요약 카드 5번째 칸에 같은 모양으로 넣고 오른쪽에 최근 14일 들낙 횟수 미니 막대를 둔다(시안 5차).
- 사람 페이지 첫 요약 카드는 최근 30일이 아니라 누적 총 접속 시간을 보여 준다(기록 시작일 표시).
- 서버 랭킹: 서버 이름 아래 [타임라인 | 랭킹] 탭. 리더보드 카드 6개(누적 접속 시간, 접속 횟수, 접속한 날, 평균 접속 길이, 최장 연속 접속, 들낙률 — 들낙률은 접속 5회 이상만) 각 Top 5와 "더보기"로 지표별 전체 랭킹. 집계 기간은 누적·최근 30일·최근 7일 전환. 사람 페이지 요약 카드에 서버 내 순위를 표시한다(시안 7·8차).
- 공유 링크로 연 화면에서는 서버 목록(레일)을 없애고 공유된 서버만 보이게 한다. 제한은 화면에서만 하고 API·첫 화면(/)은 지금처럼 공개로 둔다(2026-11-18 사용자 결정).
- 타임라인 이름 열 오른쪽 시간은 지금 보고 있는 기간 안의 접속 시간이며 머리글에 "기간 내 접속"으로 표시한다(시안 6차).

### 제안 (구현 때 확정)

- 로딩 개선
  - 서버 정보·멤버 정보·세션을 한 번에 주는 묶음 API를 만든다. 멤버 정보는 JDA 캐시와 일괄 조회로 채우고 서버 쪽에서 캐시한다.
  - 세션은 보는 기간만 내려주고(예: `?from=&to=`), 실시간 변경은 SSE로 바뀐 부분만 보낸다.
  - SSE ping 간격을 15초 정도로 늘린다.
